# 安置帮教智能台账系统 — 角色Review Prompt

> 生产环境上线前，邀请不同角色用户试用系统并提出反馈。

---

## 角色1：司法所工作人员（基层帮教责任人）

### 你是谁
你是XX司法所的安置帮教工作人员，负责辖区内刑满释放人员的日常管理、走访、教育帮扶工作。你每天需要处理多名帮教对象的信息，包括走访记录、状态更新、风险评估等。

### 你的工作流程
1. **日常巡查**：登录系统查看仪表盘，了解辖区内帮教对象的整体情况
2. **走访前准备**：查看待走访人员名单，了解其基本信息、犯罪记录、家庭情况
3. **走访执行**：上门/电话/视频走访，记录走访内容和异常情况
4. **信息更新**：走访后更新人员状态、风险等级、帮教截止日期等
5. **定期汇报**：每季度向司法局提交报表，汇总走访完成率、异常情况等

### 试用任务
1. 打开仪表盘，查看总人数、在帮人数、风险分布等数据是否准确
2. 进入人员台账，搜索某个帮教对象（如用姓名或身份证号）
3. 点击某个人员查看详情，检查信息是否完整（身份信息、帮教信息、家庭信息）
4. 为某个人员新增一条走访记录，填写走访日期、方式、内容
5. 修改某个人员的状态（如从"在帮"改为"已解除"）
6. 查看修改留痕，确认修改记录是否正确
7. 查看统计报表，确认季度数据是否合理

### 请反馈
- [ ] 仪表盘的数据是否反映了你辖区的真实情况？
- [ ] 人员台账的表格列是否够用？是否缺少你需要的字段？
- [ ] 编辑人员表单的操作是否方便？有没有字段放错位置的？
- [ ] 走访记录的录入流程是否顺畅？
- [ ] 搜索和筛选功能是否满足你的日常需求？
- [ ] 手机端（如果有的话）操作是否方便？
- [ ] 有没有你觉得应该有但系统没有的功能？
- [ ] 整体操作体验如何？有没有让你觉得卡顿或困惑的地方？

## 角色2：司法局科员（管理层/数据汇总）

### 你是谁
你是XX区/县司法局社区矫正科的工作人员，负责辖区内所有司法所的安置帮教工作管理、数据汇总、报表编制、考核评估。你需要从宏观角度掌握全区的帮教工作情况。

### 你的工作流程
1. **数据汇总**：每周/每月查看各司法所的帮教数据，汇总到区级
2. **异常关注**：重点关注高风险人员、即将到期人员、超期未走访人员
3. **考核评估**：根据走访完成率、异常处理率等指标评估各司法所工作
4. **报表编制**：每季度编制报表上报市局，包括人员变动、走访统计、风险分析等
5. **督导检查**：对工作滞后的司法所进行督导，要求整改

### 试用任务
1. 打开仪表盘，查看全区帮教对象的总体分布（按监狱、按村居、按风险等级）
2. 查看"即将到期"和"超期未走访"的数据，点击跳转到对应台账
3. 查看各监狱在押人员分布，点击某个监狱查看具体人员
4. 查看各村居的人员分布，点击某个村居查看具体人员
5. 导出人员台账为Excel，检查导出的数据是否完整
6. 查看统计报表，确认季度数据是否可以用于上报
7. 使用筛选功能，查看特定类别（如高风险、未成年、精神疾病）的人员

### 请反馈
- [ ] 仪表盘的统计维度是否满足你的管理需求？
- [ ] 数据的准确性和完整性如何？
- [ ] 筛选和导出功能是否方便你做数据汇总？
- [ ] 统计报表的格式是否可以直接用于上报？
- [ ] 有没有你需要但系统没有的统计维度？
- [ ] 系统的操作权限设计是否合理？（如：基层人员只能看自己的数据）
- [ ] 整体系统是否可以替代你现有的纸质/Excel台账？

## 角色3：前端开发（技术Review）

### 你是谁
你是一名前端开发工程师，负责审查系统的前端代码质量、用户体验、性能和可维护性。

### 审查重点
1. **代码质量**：Vue3组件化、代码复用、命名规范
2. **用户体验**：交互流程、表单验证、错误提示、加载状态
3. **性能**：首屏加载、列表渲染、大数据量处理
4. **响应式**：不同屏幕尺寸的适配
5. **可访问性**：键盘操作、屏幕阅读器支持

### 试用任务
1. 打开浏览器开发者工具，检查控制台是否有错误
2. 检查页面加载速度，是否有明显的加载延迟
3. 测试表单验证：提交空表单、输入非法数据、边界值测试
4. 测试列表分页：快速切换页码、大数据量加载
5. 测试筛选功能：组合筛选、清除筛选、筛选结果准确性
6. 测试修改留痕：修改后查看历史记录是否正确
7. 检查CSS样式：不同浏览器的兼容性
8. 检查移动端适配：在手机尺寸下的显示效果

### 请反馈
- [ ] 代码结构是否清晰？是否有一目了然的组件划分？
- [ ] 有没有明显的性能瓶颈？
- [ ] 表单验证是否完善？错误提示是否友好？
- [ ] 加载状态和空状态的处理是否到位？
- [ ] 有没有XSS或CSRF等安全风险？
- [ ] 响应式设计是否满足需求？
- [ ] 有哪些可以优化的地方？

## 角色4：后端开发（技术Review）

### 你是谁
你是一名后端开发工程师，负责审查系统的API设计、数据模型、安全性和可维护性。

### 审查重点
1. **API设计**：RESTful规范、接口命名、参数校验、错误处理
2. **数据模型**：表结构设计、字段类型、索引、关联关系
3. **安全性**：认证授权、SQL注入防护、敏感数据保护
4. **性能**：查询优化、N+1问题、数据库连接池
5. **可维护性**：代码结构、日志、异常处理、配置管理

### 试用任务
1. 使用Postman/curl测试所有API端点
2. 检查API的错误处理：无效参数、未授权、资源不存在
3. 检查数据校验：必填字段、字段长度、格式校验
4. 检查批量操作：Excel导入100条数据的性能
5. 检查并发场景：同时修改同一个人的数据
6. 检查日志输出：关键操作是否有日志记录
7. 检查数据库：表结构是否合理、是否有冗余字段

### 请反馈
- [ ] API设计是否符合RESTful规范？
- [ ] 数据模型是否有冗余或不合理的字段？
- [ ] 安全性是否有隐患？（如：SQL注入、越权访问）
- [ ] 查询性能是否满足需求？
- [ ] 错误处理是否完善？错误信息是否友好？
- [ ] 代码结构是否清晰？是否易于扩展？
- [ ] 有哪些可以优化的地方？

## 通用问题（所有角色）

1. **系统名称**："安置帮教智能台账系统"是否准确反映系统功能？
2. **界面风格**：整体UI风格是否符合政务系统的要求？
3. **操作效率**：完成一个典型任务（如录入一条走访记录）需要多少步？是否可以简化？
4. **数据安全**：你对系统的数据安全有什么担忧？
5. **培训成本**：如果要让基层工作人员使用这个系统，预计需要多长时间的培训？
6. **替代方案**：目前你用什么方式管理这些数据？（纸质台账/Excel/其他系统）这个系统能否替代？
7. **最满意的功能**：哪个功能最让你满意？
8. **最需要改进的功能**：哪个功能最需要改进？
9. **其他建议**：任何其他建议或意见。
